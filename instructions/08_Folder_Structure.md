## Rules for This Structure

1. **One folder = one responsibility.** If a new piece of logic doesn't clearly belong in an existing
   folder, stop and ask before inventing a new top-level folder.
2. **Every `src/` subfolder mirrors into a `tests/` subfolder with the same name.** This is
   non-negotiable — it's what keeps testing navigable as the system grows.
3. **No logic lives directly in `src/` root.** Everything belongs inside a named subfolder.
4. **`instructions/` is never imported by application code.** It is documentation only, read by
   humans and the agent, never referenced by `src/` at runtime.
5. **If 2-3 people work in parallel later**, the intended split is: Person A owns `adapters/` +
   `checkers/`, Person B owns `risk_engine/` + `policy/` + `audit/`, Person C owns `api/` +
   `dashboard/` + `orchestrator/`. This structure is deliberately built to make that split painless —
   preserve these boundaries even if only one person is working right now.
6. **Config values never live in code.** Anything that might change per environment or per use case
   goes in `configs/*.yaml`, not hardcoded in `.py` files.
